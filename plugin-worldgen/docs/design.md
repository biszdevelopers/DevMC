# WorldGen Plugin — Design

Status: current. This plugin owns terrain generation, wilderness regeneration,
change/mining detection, resource accounting, and points of interest. The
settlement/occupation layer is intentionally not part of this plugin; it will be
rebuilt later as a separate consumer plugin (see section 10).

## 1. Scope

- **World lifecycle**: creates or adopts the managed world, applies gamerules,
  difficulty, world border, spawn, and pregeneration.
- **Terrain**: vanilla terrain and caves shaped into a bounded island, with a
  climate-driven biome table (`docs/worldgen.md`).
- **Wilderness regeneration**: change-driven and resource-driven chunk resets.
- **Change detection**: player and non-player changes mark chunks dirty; a
  sampled terrain backstop catches anything the events miss.
- **Resources**: ores, plants, and animals are placed by the feature pass; the
  number of resource nodes placed becomes the chunk's baseline for scheduling.
- **POIs**: small destructible structures from schematics, or the built-in
  dungeon fallback.

## 2. World lifecycle and setup

`WorldGenPlugin.onEnable` loads settings, then `SetupService` runs
idempotently:

1. **world** — create or adopt the configured world with
   `WorldGenerators.create(settings)`. A random seed is re-rolled up to 24 times
   until the `isLandWorld` quality checks pass (center above sea level, at least
   65% of 12 ring samples are land, at least one sample above sea level + 45).
2. **gamerules** — apply `setup.gamerule.*` (reflection over `GameRule` fields,
   names normalized so `doDaylightCycle` matches `DO_DAYLIGHT_CYCLE`).
3. **difficulty** — `setup.difficulty`.
4. **spawn** — keep the existing spawn or adopt the caller's reference location.
5. **border** — island size when the island generator is on, else
   `setup.border_size`; centered on spawn.
6. **generate** — start `AreaRegenerator` pregeneration (radius from
   `pregen.radius_chunks`, derived with a cap of 12 chunks when unset).

Setup state is persisted in `worldgen/state.json`; when complete, later starts
only adopt the world and re-apply gamerules/difficulty, so rule changes take
effect without recreating the world.

## 3. Regeneration model

There is no state enum; each tracked chunk is a `ChunkState` record with clocks
and flags (`dueAt`, `lastPresenceAt`, `lastEditAt`, `dirty`, `pinnedUntil`,
`baselineNodes`, `extractedNodes`). Two triggers feed the same reset pipeline:

- **Dirty (fast) regeneration** — any change marks the chunk dirty; once no
  non-spectator player is within `regen.player_radius_chunks` and
  `regen.fast_regen_seconds` have passed since the last edit, the chunk is fully
  reset.
- **Resource cycle** — mined ores and opened containers count as extraction;
  once `regen.depletion_nodes` have been extracted, the chunk is scheduled at
  `now + regen.cycle_seconds + jitter`. The jitter is a deterministic hash of
  world/x/z, so resets trickle out instead of bursting.

A reset runs only when the chunk is due, unpinned, past `regen.grace_seconds`
since the last activity, and unoccupied. Untouched chunks are never reset, but
player presence still creates tracking state with an estimated baseline.

### Scheduler

`RegenerationScheduler` runs two loops on the main thread:

- **evaluate** every `regen.evaluate_interval_seconds` (minimum 20 ticks):
  updates presence, schedules/extracts, and queues due resets.
- **process** every tick: `regen.chunks_per_tick` full resets under a
  `regen.budget_millis_per_tick` wall-clock budget (the first chunk of a tick
  always runs). Blocked chunks are re-queued. The fast queue has no chunk cap
  but the same time budget; occupied entries are dropped and re-added by the
  next evaluation.

### Reset pipeline

1. `ChunkRegenerator.regenerate` restores the barebone terrain from a same-seed
   scratch world.
2. Optional vanilla-ore stripping when `regen.strip_ores` and
   `regen.vanilla_ores` are both true.
3. `FeatureGenerator.apply` re-runs ores, POIs, (disabled) loot, plants, and
   animals with a per-chunk RNG derived from the world seed, coordinates, and
   the low 16 bits of wall-clock time, so resets re-roll features.

Backends: `WorldEditChunkRegenerator` (single bulk WorldEdit copy, can strip
ores) when WorldEdit is present, else `NoopChunkRegenerator` +
`ScratchRegenerator` (per-block palette snapshot restore). Both copy from a
`<world>_regen` scratch world generated by the same generator, so terrain
matches exactly.

## 4. Change detection

- `WildernessListener` marks chunks dirty on break/place, container
  right-click, entity/block explosions, block burn, and block changes by
  endermen, the ender dragon, withers, and ravagers. Mined ores and opened
  containers deplete nodes. Death drops pin the chunk for
  `regen.drop_pin_seconds`. Natural processes (leaf decay, snow melt, grass
  spread) are deliberately ignored so the feature pass does not re-dirty its own
  output; a 3 second settling window suppresses non-player events caused by a
  reset itself.
- `WildernessIntegrityListener` is the backstop: on chunk unload it samples a
  4×4 grid against the scratch world (when `regen.verify_changes` is on) and
  marks the chunk dirty if the live surface is missing terrain. It does not
  deplete nodes or pin.

## 5. Resource accounting

`FeatureGenerator.apply` returns the number of resource nodes placed (ore
blocks + POIs + loot caches) and the scheduler stores it as `baselineNodes`.
`extractedNodes` accumulates mining and container use; the HUD and
`/worldinfo` report the remaining ratio. Legacy chunks get an estimated
baseline from the ore table.

## 6. Points of interest

`PoiService` rolls `small_structure.chance` per chunk (disabled by
`structures.enabled`, capped by `structures.poi_cap` on an in-memory live set).
It pastes a random registered schematic at the surface through the WorldEdit
structure bridge and, when no schematic or bridge is available, falls back to
`SmallStructures` — a cobblestone room with a zombie spawner and cobwebs.
POIs are ordinary destructible blocks; the next regeneration erases and re-rolls
them. Loot filling and the built-in dungeon chests are currently disabled.

## 7. Admin dimension, snapshots, simulator

- `AdminDimensionService` manages a flat `storage.dimension` world (default
  `world_admin`) excluded from world rules, with a staging chunk at 4096/4096.
- `ChunkSnapshot` is the palette snapshot used by the scratch restore; its
  `synthetic` variant builds a deterministic test column.
- `SnapshotStore` persists named snapshots in `worldgen/snapshots.json` (no
  command surface yet).
- `RegenerationSimulator` stages a snapshot in the admin dimension and reports
  ore/container counts before and after simulated cycles; `RegenSelfTest`
  (`debug.verify_regen`) forces one reset at startup and logs the result.
- `/worldadmin` currently exposes reload, diag, pregen, cycle, regenerate,
  clear, hud, and poi; `/worldinfo` exposes the console diagnostics.

## 8. Configuration and data

All defaults and keys are described in `README.md`; settings live in
`ServerData/worldgen/settings.json` and are merged default-only on enable.
Data files: `worldgen/wilderness.json`, `worldgen/state.json`,
`worldgen/snapshots.json`, `worldgen/structures.json`, `worldgen/loot.json`,
plus schematics under `worldgen/structures/`.

## 9. Deferred: occupation layer

The former settlement/plot/rent/protection/zone/police/vendor/monument systems
were removed with the `plugin-city` split being deferred. When rebuilt as a
consumer plugin on top of worldgen, regeneration exemptions (settlement chunks,
monuments) can be reintroduced as a registration hook in
`RegenerationScheduler.enqueueChunk` and the wilderness predicates.
